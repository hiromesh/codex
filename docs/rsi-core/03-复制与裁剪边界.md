# 复制与裁剪边界

已确定的能力范围见 [决策记录](06-决策记录.md#d-014-codex-正在被并行裁剪能力清单冻结)，功能迁移顺序见 [Codex 功能迁移顺序](11-codex功能迁移顺序.md)。每个 feature 按实际调用路径迁移源码与依赖。

## 1. 原则

| 原则 | 说明 |
|---|---|
| 结构跟 codex 一致 | workspace、crate、模块路径尽量不改，方便对照 |
| 按 feature 抄 | 一次只抄一块能跑起来的子集，不整体 fork |
| 先关后删 | 能用 feature flag / 配置关掉的，先关；稳定后再删 |
| 不为干净提前重构 | 先抄进来，再在对应 feature 里删/改 |
| 硬约束写进代码 | 工具面、路径、预算不靠提示词 |
| 事件稳定 | 面板/证据/成本读同一份流 |
| 记录来源 | 每块记录 codex commit 或工作区快照 |

## 3. 删除

### 3.1 云端与产品服务

`core-api`、`cloud-config`、`cloud-tasks*`、`cloud-client`、`backend-client`、`codex-backend-openapi-models`、`external-agent-migration`、`responses-api-proxy`、`stdio-to-uds`、`tcp-tunnel`、`v8-poc`、`thread-manager-sample`、`test-binary-support`。

### 3.2 界面

`tui`、`ansi-escape`、`mermaid`，以及只服务 TUI 的 `utils/cli`、`utils/fuzzy-match`、`utils/oss`、`utils/approval-presets`、`utils/sandbox-summary`、`utils/sleep-inhibitor`、`utils/elapsed`。

### 3.3 插件、图片生成与远程执行环境

移除插件包、插件加载与管理、插件市场和插件宿主；移除 `ext/image-generation` 及图片生成和编辑专属接口；移除远程执行环境连接、远程进程与文件系统实现和跨环境文件复制。插件相关 crate 中被 MCP、Hooks、Skills 或本地执行使用的共享代码按实际依赖处理。

内核扩展注册、MCP、Hooks、Skills、多智能体与长期目标保留对应接线。

### 3.4 实时、语音、认证、遥测

`realtime-*`、`voice-host`、`realtime-webrtc`、`chatgpt`、`aws-auth`、`keyring-store`、`workload-identity`、`user-verification`、`otel-trace-websocket`、`feedback`、`analytics`、`otel`、`login` 的产品功能。多模态上下文所需的输入类型和处理代码按实际依赖保留。

### 3.5 平台与网络

`windows-sandbox-*`、`mxc-sandbox`，以及按实际调用关系确定的产品辅助功能。模型网关、网页搜索和 MCP 所需的网络通信、本地文件访问和执行环境按功能保留。

### 3.6 搁置（暂不决定）

以下能力的具体实现范围在对应 feature 中确定。

| 区域 | 说明 |
|---|---|
| `skills`、`ext/skills` | 技能机制；RSI 阶段说明可能由框架注入，也可能需要技能 |
| `codex-mcp`、`rmcp-client` | 确定需要，但放到 F5 |
| `state`、`thread-store` | 持久化/恢复；等 D-012 |
| `rollout`、`rollout-trace` | 事件/轨迹；等 D-007 |

| 新增 | 内容 |

## 6. 对裁剪分析的修正

| 裁剪分析的说法 | 代码实际 | 建议 |
|---|---|---|
| `codex-api` | 承载 Responses、搜索和记忆等接口 | 迁移所需模型、搜索和记忆接口；移除图片生成与编辑专属接口 |
| `exec-server` | 本地与远端共享部分协议和代码 | 迁移本地执行及所需共享实现；移除远程执行环境 |
| TUI | 使用 `app-server-protocol`、`app-server-client`、`state` 等组件 | 调试终端使用 app-server 协议连接 Agent 进程 |
| `protocol` 33k 行 | 依赖 `network-proxy`、`execpolicy`、`utils-image` 等 | 按 feature 抄类型子集，不整块搬 |
| `codex-client`/`http-client` 未被单列 | 它们是模型链路的底座 | 必须保留（至少最小传输） |

## 7. 分阶段

| 阶段 | 删除/保留重点 |
|---|---|
| 第一阶段 | 建立 workspace、模型链路、会话接口和 app-server WebSocket 通信 |
| 第二阶段 | 工具循环、会话/上下文、本地执行与沙箱、多模态输入 |
| 第三阶段 | MCP、Hooks、搜索、多智能体、记忆、长期目标与持久化 |
| 收尾 | 删除不再需要的 crate、清理 feature flag、补文档与测试 |
