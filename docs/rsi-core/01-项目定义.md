# 项目定义

## 一句话

`rsi-core` 是从 codex 裁剪、复刻出来的 Rust agent 内核；先完成内核，再在内核之上做全 Rust 的 RSI 框架。

## 背景

参考材料：

- [codex 仓库](/Users/hiro/codex)：上游基线，当前工作区已做过 Windows/Ollama/cloud-client 等裁剪。
- [codex 内核裁剪分析](/Users/hiro/codex/docs/codex-内核裁剪分析.md)：逐 crate、逐模块的保留/删除/替换决策。
- [RSI 平台设计讨论](/Users/hiro/ugc-platform/docs/rsi/RSI平台设计讨论.md)：系统组成、内核边界、job 契约、一个周期的九个阶段。
- [RSI 调研与 Agent 系统改进报告](/Users/hiro/rsi/RSI_调研与Agent系统改进报告.md)：RSI 的八个组成部分与实现选择。

RSI 的 Agent 需要：读大量证据、提出假设、在工作区里改文件、调用实验工具、自我批评、产出可辩护的结论。这要求文件系统、多轮工具调用、上下文压缩、沙箱、结构化事件流。codex 已经有这些，并且有明确的裁剪边界；直接重写一遍不如按层复刻，再按 RSI 的需要改造。

## 命名说明

设计文档 §3 里：

- `rsi-core`：Python 服务，负责编排、证据、评测、裁决、交付。
- `rsi-kernel`：从 codex 裁剪出来的 Rust 二进制，按阶段启动，跑一次受限会话。

本仓库名叫 `rsi-core`，但承担的是 `rsi-kernel` 的角色；后续的 RSI 框架也确定用 Rust 写。为避免混淆，本文档统一这样称呼：

- **rsi-core**：本仓库，Rust agent 内核。
- **rsi 框架**：后续的 RSI 编排/证据/评测/裁决层，也是 Rust。

如果以后要和设计文档的命名对齐，可以再把二进制/包名调整；不影响当前架构。

## 目标

### 内核完成时（草案）

1. 读一份 job 描述，启动一次受限会话，写出结构化输出与 JSONL 事件流。
2. 支持 Responses API 流式、function/custom 工具调用、多轮工具循环。
3. 内置工具面至少覆盖：读文件、改文件、跑命令、搜索、看图、MCP 工具、上下文剩余量。
4. 工作区边界、工具面、轮数/token/时间预算由代码强制，不依赖提示词。
5. 上下文压缩、系统提示装配、token 账本可用。
6. MCP 客户端与 hooks 可用。
7. 事件契约稳定，面板、证据库、成本核算能读同一份流。
8. 容器内可离线测试；真实模型使用 OpenAI Responses API。
9. 关键路径有自动测试与真实服务联调；代码可读、可改。
10. 支持多模态上下文、文件搜索与网页搜索。
11. 支持多智能体、记忆和长期目标。
12. 提供独立的 `app-server`，通过 WebSocket 和 JSON-RPC 连接调试终端。

### 非目标

- TUI 不迁移；只保留一个最简终端调试入口（`rsi` 的 exec/REPL），未来也可以删掉。
- IDE 集成。
- 云端任务、插件、连接器。
- ChatGPT 登录、AWS/GCP 认证、密钥环。
- 自动审查（Guardian）、实时语音、代码模式。
- 图片生成与编辑、远程执行环境。
- 遥测上报、分析埋点、反馈上传。
- Windows/macOS 沙箱。
- RSI 的证据、统计、裁决、Git、面板逻辑（属于后续 rsi 框架）。

## 工作方式

按 feature 垂直迁移，不整体 fork：

1. 在 [迁移路线](05-迁移路线.md) 里认领一个 feature，写清范围、codex 来源、验收。
2. 只复制这个 feature 需要的最小代码子集；导入路径统一改成 `rsi_core_*`。
3. 完成编译、运行和测试；使用真实依赖进行端到端验证。
4. `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test` 全绿。
5. 提交一个 commit，更新决策记录与迁移路线。
6. 再开始下一个 feature。

复制原则：

- 目录/模块划分尽量跟 codex 一致，方便对照和后续同步。
- 不为了“干净”提前重构；先抄进来，再在对应 feature 里删。
- 不复制 codex 的测试（测试占 codex 近一半代码量）；只抄与协议/边界强相关的 fixture，其余自己写。
- 每块记录来源 commit 或工作区快照，见 [D-008](06-决策记录.md#d-008-记录-codex-来源快照)。
- 保留 Apache-2.0 归属：根目录放 `LICENSE`/`NOTICE`，复制文件不删版权头（codex 源码大多没有文件头，则在 `NOTICE` 里说明来源）。

## 完成标准

“rsi-core 完成”不是“codex 的所有 crate 都搬完”，而是：

- 目标能力齐备（见上）；
- 不需要的子系统已经删除或隔离；
- 一份 job 能在容器里稳定跑完；
- 失败路径可诊断；
- 新接手的人能通过文档和代码读懂它。
