# 决策记录

状态说明：**已定** = 用户确认；**暂定** = 当前方案，讨论后可改；**待定** = 还没结论。

## D-001 全 Rust

- 状态：已定（2026-11-03）
- 背景：设计文档里 `rsi-core` 是 Python 服务、`rsi-kernel` 是 Rust 二进制。用户明确“后续全部是 rs 写”。
- 决策：本仓库先做 Rust agent 内核；后续的 RSI 框架也用 Rust。设计文档里的 Python 假设作废。
- 影响：
  - 未来的编排/证据/评测/裁决/面板接口都会是 Rust crate/二进制。
  - 内核可以设计成库 + 二进制；框架可以子进程调用，也可以同进程嵌入（见 D-011）。
  - 不再需要跨语言 FFI/HTTP 作为内核边界，但保留进程边界仍有隔离价值。

## D-002 工作区与 crate 命名用 `rsi-core-*`

- 状态：已定（2026-11-03）
- 背景：从 codex 复制代码时，目录、包、类型名可以保留 `codex-*` 以便对照，也可以立即改成 `rsi-core-*`。
- 决策：立即改。workspace 根目录 `rsi-core-rs`；crate 目录与包名 `rsi-core-protocol`、`rsi-core-client`、`rsi-core-http-client`、`rsi-core-api`、`rsi-core-model-provider-info`、`rsi-core`、`rsi-core-cli`；导入路径 `rsi_core_*`；二进制 `rsi-core`。
- 影响：
  - 与 codex 的 diff 会有命名噪声；对照时用原始文件。

## D-003 按 feature 垂直迁移

- 状态：已定（2026-11-03）
- 背景：codex 有 145 个 workspace member；整体 fork 后裁剪的调试面太大。
- 决策：一次只抄一个能编译/运行/测试的 feature 子集；不整体复制 `codex-rs`。
- 影响：
  - 每个 feature 需要自己切依赖子集，可能临时写最小实现。
  - 早期代码与 codex 有差异；后续 feature 逐步收敛。
  - 每次提交应能独立回滚。

## D-004 模型接入 OpenAI Responses API

- 状态：已定（2026-11-03）
- 决策：模型接入使用 OpenAI Responses API，其他模型服务商的接入功能不迁移。
- 影响：
  - 验证 Responses API 的流式响应、function 工具、工具结果回传和 reasoning item 行为。
  - 模型请求使用 Responses 协议。
  - `store=false`，会话历史由内核管理。

## D-005 调试终端与应用服务

- 状态：已定（2026-11-03）
- 背景：终端前端用于调试，Agent 会话可以运行在独立进程中。
- 决策：调试入口使用 `rsi-core exec` 和 `rsi-core chat`，提供纯文本输入输出。独立 app-server 使用 JSON-RPC 和 TCP WebSocket 与客户端通信。TUI 不迁移。
- 补充决策（2026-11-03）：WebSocket 的可选 zstd-stream 压缩与 HTTP 健康检查端点（`healthz`、`readyz`）不纳入迁移范围。
- 影响：
  - 会话创建、输入提交、事件通知、中断和会话恢复通过 app-server 协议传递。
  - 终端可以直接使用内核接口，也可以连接独立 app-server。
  - 前端代码集中在 `cli` crate。

## D-006 目标运行环境是 Linux 容器

- 状态：暂定（2026-11-03）
- 背景：设计文档的部署形态是容器；开发机是 macOS。
- 决策：生产目标是 Linux 容器；开发期允许 macOS 上跑单测/mock，但涉及沙箱/进程的语言特性以 Linux 为准。
- 影响：
  - Windows/macOS 沙箱代码不抄。
  - Landlock/bwrap 是候选；seatbelt 不抄。
  - CI 应至少覆盖 Linux；macOS 只做编译/单测。

## D-007 事件契约自建

- 状态：暂定（2026-11-03）
- 背景：codex 的 `protocol::EventMsg` 与 app-server/TUI 绑定；RSI 的面板/证据/成本需要更小、更稳定的 schema。
- 决策：定义 rsi 自己的 JSONL 事件 schema；内部从 `ResponseEvent`、工具结果、预算状态映射。可借鉴 `rollout` 的写法，但不直接暴露 `EventMsg`。
- 影响：
  - 需要设计事件版本/兼容策略。
  - 不能免费复用 codex 的恢复/回放逻辑；如果需要，另做适配。
  - 事件字段一旦对外，改动需要兼容期。

## D-008 记录 codex 来源快照

- 状态：已定（实践）
- 背景：codex 工作区正在变化（Windows/Ollama/cloud-client 裁剪），复制时可能拿到半成品。
- 决策：每个 feature 开始时记录来源：commit hash + 工作区状态（`git status`/`git diff --stat`）；如果工作区不干净，优先让 codex 侧先提交/打 tag，或只从 HEAD 复制不受影响的部分。
- 影响：
  - 文档/commit message 里能看到“这块来自哪个快照”。
  - 后续同步 codex 改动时有基线。

当前快照：`fbe36e2382` + 未提交的 Windows 清理（约 364 文件、1.1 万行删除）。

## D-009 保留 Apache-2.0 归属

- 状态：已定（实践）
- 背景：codex 是 Apache-2.0；复制代码需要保留许可证与归属。
- 决策：根目录放 `LICENSE`（Apache-2.0）与 `NOTICE`，说明来源于 OpenAI codex；复制的文件不删版权头（若有）。
- 影响：
  - 发布二进制/镜像时带上 NOTICE。
  - 修改过的文件在 commit message 里注明来源。

## D-010 第一个 feature 是 F2 工具循环

- 状态：已定（2026-11-03）
- 背景：用户确认第一轮做 F2 工具循环；F0/F1 作为它的前置子步骤，不单独成轮。
- 决策：第一轮交付一个可跑的多轮工具循环：Responses 流式 + function/custom tool call + 工具执行 + 结果回写 + 预算终止 + 终端调试。
- 影响：
  - 需要先打通模型链路（原 F1），所以 F2 的实际范围比“只做工具路由”大。
  - 工具面先小：`read_file`、`shell`，`apply_patch` 是否本轮包含待讨论。
  - 前端只做终端；不做 TUI。
  - 事件先最小化，schema 后续演进。

## D-011 内核与框架的进程边界

- 状态：暂定（2026-11-03）
- 背景：设计文档 §6.5 用子进程，每个阶段一个进程、一次会话；全 Rust 后也可以库调用。
- 决策倾向：保留子进程边界；job 用文件/JSON 传入，事件/输出写文件，退出码表达结果。库调用作为测试/嵌入模式后加。
- 影响：
  - 隔离、成本可预测、阶段可重试。
  - 需要定义 job/事件/退出码契约。
  - 如果后续发现子进程开销/调试不便，可再加库模式，不影响契约。

## D-012 持久化/断点续跑

- 状态：待定
- 背景：codex 有 `state`/`thread-store`/`rollout`；RSI 的会话是短生命周期，是否要断点续跑取决于框架重试策略。
- 倾向：第一期不做数据库；事件/输出落文件即可。需要恢复时再评估 `rollout` 或自建。
- 影响：不做恢复则阶段失败只能整段重跑；做恢复则要持久化历史与工具状态。

## D-013 沙箱形态

- 状态：待定
- 背景：设计文档要求“工作区外不可读写”，但容器本身已是边界；设计文档又说容器内完全开放。
- 选项：
  1. 只靠容器 + 运行用户权限，不做进程内沙箱。
  2. 容器内再加 Landlock（Linux），限制到 workspace。
  3. 用 bwrap/namespace 包一层。
- 影响：直接决定 F4 的范围，以及 `exec-server`/`sandboxing` 要抄多少。

## D-014 codex 正在被并行裁剪，能力清单冻结

- 状态：已定（2026-11-03）
- 背景：codex 仓库里有很多 agent 在删除不需要的功能；但我们未来需要的能力不会变。
- 决策：
  - 以“rsi-core 需要的能力”为准，不以 codex 当前删到哪一步为准。
  - 保留多模态上下文、文件搜索、网页搜索、多智能体、记忆和长期目标。
  - 移除图片生成与编辑、远程执行环境和插件功能；本地执行环境、内核扩展注册、MCP 与 Hooks 继续保留。
  - 复制时仍然记录来源快照（D-008）；如果 codex 删掉了我们以后要用的代码，从历史 commit 取。
- 影响：
  - 多模态输入所需的图片处理、附件、协议和工具结果类型按实际依赖迁移。
  - 模型网关、网页搜索和 MCP 的网络连接按对应功能迁移。
  - 需要时可以从 codex 的 git 历史恢复被删模块。

## D-015 终端前端可丢弃

- 状态：已定（2026-11-03）
- 背景：用户明确不需要 TUI；前端只为 debug 方便，未来也不需要。
- 决策：前端放在薄 `cli` crate，只做 `exec`/`chat` 的纯文本输入输出；不引入 ratatui、不做全屏、不做复杂状态管理。
- 影响：
  - 内核库独立于前端；前端使用内核公开 API 或 app-server 协议。
  - 以后删掉前端不影响内核与测试。
  - 调试信息优先写进事件流/日志，而不是只打在终端。
