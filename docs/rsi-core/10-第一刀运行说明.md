# 模型会话与事件通道

## 会话接口

`ThreadManager` 创建和管理会话线程。`CodexThread` 使用提交队列接收输入与中断操作，通过事件队列发送回合状态、文本增量、模型输出条目、Token 用量和错误。回合运行期间可以继续读取会话历史，也可以向当前回合提交引导输入。

会话保留完整的消息和 reasoning 条目，并在后续 Responses 请求中回传。`store=false` 时，请求包含 `reasoning.encrypted_content`。会话历史保存在内存中。

调试终端通过会话接口提交输入，支持单次执行、多轮对话、创建新会话、查看累计用量和中断当前回合。调试终端也可以通过 WebSocket 连接独立 app-server；消息使用 Codex app-server 的 JSON-RPC 格式。服务与客户端包含适配当前内核接口的代码，覆盖会话创建、读取、恢复、回合提交、引导、中断和事件通知。服务进程保留运行中的会话，客户端重新连接后可以恢复该会话。

## 模型服务配置

模型服务使用 Responses API。配置文件指定 `model`、`model_provider` 和对应的 `model_providers`，服务地址使用 `base_url`，认证信息从 `env_key` 指定的环境变量读取。

可配置的模型参数包括 `model_reasoning_effort`、`model_reasoning_summary` 和 `service_tier`。服务配置支持请求超时、流式空闲超时、请求重试次数和流式重试次数；`supports_websockets` 控制 Responses WebSocket 传输。

## 运行与验证

在 `rsi-core-rs` 目录使用实际的 `rsi.toml` 和配置中指定的认证环境变量运行：

```bash
cargo run -p rsi-core-cli -- --config rsi.toml exec --prompt "你好"
cargo run -p rsi-core-cli -- --config rsi.toml chat
```

启动独立 app-server，并在另一个终端连接：

```bash
cargo run -p rsi-core-cli -- --config rsi.toml app-server --listen ws://127.0.0.1:8765
cargo run -p rsi-core-cli -- --connect ws://127.0.0.1:8765 chat
```

真实服务测试覆盖多轮对话、模型输出条目、reasoning 回传、用量、回合引导、中断与后续对话、错误响应和会话关闭。独立进程测试覆盖 TCP WebSocket 通信、会话恢复和中断。Responses WebSocket 测试使用支持该传输方式的真实服务。
