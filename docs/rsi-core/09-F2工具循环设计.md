# F2 工具循环：设计与讨论

> 状态：第一轮 feature 已定（2026-11-03）。第一刀（M0 + M1：workspace + 流式 + 多轮对话，无工具）已完成，见 [10-第一刀运行说明](10-第一刀运行说明.md)。工具面、`apply_patch` 形态、shell 是否本轮做，仍待确认。工具迁移的依赖闭包与分层顺序见 [02-codex架构地图](02-codex架构地图.md) 第 4、5 节；简化实现不做，范围确认后按忠实闭包迁移。

## 1. 目标

让内核完成一个最小的 agent 闭环：

```text
user message
  -> model（带 tools）
  -> function_call / custom_tool_call
  -> 内核执行工具
  -> function_call_output / custom_tool_call_output
  -> model
  -> ... 直到没有工具调用，或预算/错误终止
  -> final text + usage + events
```

交付物：

1. 一个能跑多轮工具调用的 `rsi-core` 终端程序。
2. 至少两个只读工具（`read_file`、`grep`/`glob`），验证“多工具、多轮、错误回传”。
3. 一个写工具（`apply_patch`），验证“模型改文件”闭环（可作为 F2.1）。
4. 最小 JSONL 事件，方便 debug 和后续面板/证据。
5. mock SSE 测试 + 真实网关 smoke。

## 2. 非目标

- 上下文压缩、token 预算执行（只记录 usage）。
- MCP、hooks。
- 完整沙箱/exec-server（路径边界做最小版）。
- job 描述、结构化输出、持久化/恢复。
- TUI/全屏界面。
- 多智能体、插件、消息板、记忆。

## 3. 最小状态机

```text
Idle
  -> Sampling           发请求，流式收事件
  -> ToolCalls          收到一个或多个 call，追加到 history
  -> Executing          逐个执行工具，追加 output
  -> Sampling           带着工具结果再采样
  -> Done / Budget / Error
```

规则：

- 一个回合内可以有多个工具调用；先串行执行，后续再考虑并发。
- 工具执行失败也写 `function_call_output`，把错误文本回给模型，不中断会话。
- 达到 `max_turns`、`deadline`、连续无进展时终止，保留已产生的事件与历史。
- 历史是 `Vec<ResponseItem>`，只在内存；持久化后置。

## 4. crate 结构

沿用 [07-模型调用链路笔记](07-模型调用链路笔记.md) 的规划：

```text
rsi-core/
  rsi-core-rs/                  # Rust workspace
    Cargo.toml
    rust-toolchain.toml
    rustfmt.toml
    rsi-core-protocol/          # ResponseItem 子集、TokenUsage
    rsi-core-client/            # Provider/retry/SSE
    rsi-core-http-client/       # reqwest 最小传输
    rsi-core-api/               # Responses 请求与 SSE 解析
    rsi-core-model-provider-info/
    rsi-core/                   # config、session loop、tool registry/handlers、events
    rsi-core-cli/               # exec / chat
```

前端只依赖 `rsi-core` 的公开 API；内核不依赖前端。

## 5. 模型链路

- 只支持 Responses，`stream=true`、`store=false`。
- `input` 第一项是 developer message，内容为 codex 的 `base_instructions/default.md`（已翻译为中文）；后面是 user/assistant 历史。
- 请求带 `tools`、`tool_choice="auto"`、`parallel_tool_calls=false`。
- 解析 SSE：
  - `response.output_text.delta` → 终端增量输出。
  - `response.output_item.done` → 完整 `ResponseItem`；识别 `function_call`/`custom_tool_call`。
  - `response.completed` → usage、response_id、end_turn。
  - `response.failed`/`error` → 结构化错误。
- 工具结果作为 `function_call_output` 追加到下一轮 input；不重新发 system/user 的完整请求（Responses 的 input 是完整历史）。

## 6. 工具协议

### 6.1 工具描述

第一期只用 function 工具：

```json
{
  "type": "function",
  "name": "read_file",
  "description": "Read a UTF-8 text file inside the workspace.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": {"type": "string"},
      "offset": {"type": "integer"},
      "limit": {"type": "integer"}
    },
    "required": ["path"],
    "additionalProperties": false
  }
}
```

`apply_patch` 有两种候选：

- **function 工具**：`{"patch": "*** Begin Patch ..."}`，网关兼容性好。
- **custom/freeform 工具**：codex 原样，`input` 是纯文本 patch；需要网关支持 `type: "custom"`。

建议先用 function 工具，等网关验证支持 custom 后再切换。

### 6.2 工具调用/结果

```json
{"type":"function_call","name":"read_file","arguments":"{\"path\":\"README.md\"}","call_id":"call_1"}
{"type":"function_call_output","call_id":"call_1","output":"..."}
```

注意：

- `arguments` 是 JSON **字符串**，需要二次解析。
- `output` 是字符串（或 content items）；先用字符串，便于模型消费。
- 工具结果要截断（例如 64KB），并标注“已截断”。

### 6.3 工具接口

```rust
#[async_trait]
pub trait Tool: Send + Sync {
    fn spec(&self) -> ToolSpec;
    async fn execute(&self, call: ToolCall, ctx: &ToolContext) -> ToolResult;
}
```

`ToolContext` 至少包含：workspace root、只读/可写标志、超时、输出上限、事件 sink。
`ToolResult` 包含：输出文本、是否成功、耗时、可选的结构化元数据。

### 6.4 工具注册与可见性

- 启动时按配置构造 `ToolRegistry`。
- 每个回合生成 `model_visible_specs()`，只把暴露的工具放进请求。
- 未暴露的工具即使模型“猜”到名字，也无法执行；返回 `unknown tool` 错误。
- 工具名、参数 schema 固定；不做动态工具（后置）。

## 7. 工具候选

| 工具 | 价值 | 复杂度 | 建议 |
|---|---|---|---|
| `read_file` | 读证据/代码，诊断必需 | 低 | F2 必做 |
| `grep` / `glob` | 搜索证据/代码 | 中（可抄 `file-search`） | F2 做，或与 `read_file` 合并为 `search` |
| `apply_patch` | 提案阶段改文件 | 中高（patch 解析 + 路径校验） | F2.1 做 |
| `shell` | 跑命令/测试 | 高（进程、超时、输出、沙箱） | F4 做 |
| `view_image` | 看图证据 | 中 | 后置 |
| `mcp` | 框架注入证据/实验工具 | 高 | F5 |

第一轮建议：`read_file` + `grep` 先跑通 loop，再加 `apply_patch`。`shell` 不在 F2，避免把执行环境/沙箱提前拖进来。

如果希望第一轮就能“改文件”，则 F2 范围改为 `read_file` + `apply_patch`，`grep` 后置。

## 8. `apply_patch` 的三种做法

1. **function 工具 + 自写/改造 parser**
   - 复用 codex `apply-patch` 的 parser/file_update/seek_sequence；
   - 把 `ExecutorFileSystem` 换成 `std::fs`/`tokio::fs`；
   - 路径限制在 workspace；写前校验。
   - 优点：网关兼容；缺点：要改 codex 代码，和上游有 diff。

2. **custom/freeform 工具（codex 原样）**
   - 复用 `create_apply_patch_freeform_tool` 和 handler；
   - 需要网关支持 `type: "custom"` + grammar；
   - 优点：codex 一致；缺点：网关未知，可能不支持。

3. **先不做**
   - F2 只读；`apply_patch` 放到下一轮。
   - 优点：最快看到 loop；缺点：无法完成“提案”闭环。

建议：先按 1 做，保留切换到 2 的可能；如果网关支持 custom，再切回 codex 原样。

## 9. 终端前端

只做纯文本，不做 TUI。

### 9.1 `rsi-core exec`

```bash
rsi-core exec --prompt "读一下 README，总结项目目标"
rsi-core exec --prompt "..." --json
rsi-core exec --prompt "..." --events run.jsonl
```

输出：

- 模型文本增量到 stdout。
- 工具调用/结果、usage、错误到 stderr（人类可读）。
- `--json` 时 stdout 只输出最终结构化结果或 JSONL 事件（二选一，待定）。

### 9.2 `rsi-core chat`

```text
> 读一下 README
[model] ...
[tool] read_file {"path":"README.md"}
[tool] ok 1.2KB
[model] ...
> /quit
```

命令：`/quit`、`/new`（清空历史）、`/tools`（列出工具）、`/events`（切换事件显示）。不做历史滚动、不做快捷键。

### 9.3 事件显示

默认把工具调用、工具结果摘要、usage 打到 stderr；`RUST_LOG` 控制日志。事件 JSONL 可选。

## 10. 事件

F2 只做最小集合，schema 可演进：

| 事件 | 字段 |
|---|---|
| `session.started` | session_id, model, workspace, tools |
| `turn.started` | turn |
| `model.response` | response_id, usage, duration_ms |
| `tool.call` | name, call_id, arguments（截断） |
| `tool.result` | call_id, ok, duration_ms, output（截断） |
| `error` | class, message |
| `session.completed` | turns, usage, duration_ms |

实现：`EventSink` trait；默认 stderr 人类可读，`--events` 时追加 JSONL。不要一开始就做完整 schema/版本化。

## 11. 预算与终止

F2 最小：

- `max_turns`：默认 20，CLI 可配。
- `deadline`：可选，默认不设。
- 工具超时：默认 30s；`read_file`/`grep` 可更短。
- 输出截断：单次工具输出 64KB；超出标注。
- 终止原因：`completed` / `max_turns` / `deadline` / `error`。

token 预算只记录，不强制；F6 再做。

## 12. 错误处理

| 错误 | 行为 |
|---|---|
| 网关 401/403 | 不重试，提示检查 `LLM_API_KEY` |
| 网关 429/5xx | 重试 2-3 次，指数退避 |
| SSE 断流 | 报错；保留已输出文本；F2 不做续传 |
| 工具参数 JSON 非法 | 返回 `invalid arguments` 给模型，不中断 |
| 工具执行失败 | 返回错误文本给模型，不中断 |
| 未知工具 | 返回 `unknown tool` 给模型 |
| 路径越界 | 返回 `path outside workspace`，不执行 |

## 13. 测试

### 13.1 单测

- `ToolSpec` 序列化。
- `function_call` 参数解析（合法/非法/缺字段）。
- `read_file`：正常、超限、路径越界、非 UTF-8。
- `grep`：匹配、无匹配、二进制文件、超大文件。
- `apply_patch`：新增/修改/删除/冲突/路径越界。
- 状态机：无工具直接完成、单工具、多工具、工具失败、max_turns。

### 13.2 mock SSE

录制/构造事件序列：

1. 纯文本 → completed。
2. function_call(read_file) → 结果 → 文本 → completed。
3. 两个 function_call → 两个结果 → 文本。
4. function_call 未知工具 → 错误 → 模型重试。
5. 工具参数非法 → 错误 → 模型修正。
6. max_turns 终止。
7. SSE error / 断流。

### 13.3 真实网关 smoke

- 纯文本。
- `read_file` 调用与结果回传。
- 多轮（读文件 → 基于内容回答）。
- `apply_patch`（如果本轮做）。
